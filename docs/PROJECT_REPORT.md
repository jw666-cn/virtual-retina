## 1. 项目概述

AI 虚拟仿生视网膜（Vision Retina）是一个**视觉输入外设**：它把屏幕或摄像头画面采集下来，按视网膜的方式做预处理与压缩，再通过标准协议交给客户自选的视觉模型（“大脑”）和执行工具（“手”）。

它解决的不是“让模型会操作电脑”，而是“让任何模型都能低成本地看见电脑”：

- **看得清**：低清全帧看版面，模型点名区域后放大看细节；
- **看得省**：脏区、静默、语义裁剪、中央凹、双路预算、场景自适应；
- **不绑定**：大脑走 OpenAI 兼容接口，手走 MCP / WebSocket；产品内没有任何模型与执行器。

一句话：**视网膜不是 Agent，是给 Agent 用的眼睛。**

### 1.1 边界（先写在前面）

| 是 | 不是 |
|---|---|
| 采集 + 仿生编码 + 标准接口 | 端到端 Agent；不做规划、不执行点击/输入 |
| 模型无关（任意 OpenAI 兼容视觉模型） | 不绑定 UI-TARS / GPT / Claude / DeepSeek |
| 手无关（MCP + WebSocket JSON） | 不依赖 dsh / openclaw / opencode 的内部实现 |
| 本地优先，默认不落盘、不上传 | 不是录屏软件，不保存历史画面 |

### 1.2 交付形态

- Python 包：`vision_retina/`（采集、总线、仿生编码、大脑/手接口、CLI）。
- 协议：MCP（stdio / Streamable HTTP）+ WebSocket `retina.ws/1`。
- 工具链：`tools/` 下自检、基准、闭环、对比脚本（不属于产品运行时）。
- 文档：`docs/`（接口、仿生设计、验收、能力摘要、开源清单）+ `reports/`（对比与验证）。

## 2. 仿生架构

设计原则：**像视网膜一样先做并行预处理，而不是把整张图原样丢给大脑。**

| 生物机制 | 数字实现 | 代码 | V1 状态 |
|---|---|---|---|
| 视杆细胞：周边、低分辨、看全局与运动 | 全帧低清（默认 768 宽）+ 脏区/差分 | `bionic.low_view()`、`bus.grid_diff` | ✅ |
| 视锥细胞：中央、高分辨、看细节 | 焦点高清（默认 1024 宽）+ 语义安全裁剪 | `bionic.focus_view()`、`roi.expand_rect_to_content` | ✅ |
| 中央凹：可编程注视点 | 模型输出 `zoom` 指令 → 按坐标放大返回 | `bionic.parse_zoom()` / `BionicRetina.ask()` | ✅ |
| 视网膜并行预处理 | 脏区、语义 ROI、静默、编码缓存 | `bus.py`、`service.py` | ✅ |
| 暗适应：静时降采样、动时提灵敏 | EMA 变化率 + 滞回三档（static/normal/dynamic） | `adaptive.AdaptiveController` | ✅ |
| 眼跳：微动采样、大脑拼接 | 多帧采样 / 注视点序列 | — | V2 |
| 盲点：无感光、大脑补全 | 区域白名单 / 关键区冗余 | `safety.region_whitelist`（白名单已做） | V2 扩展 |

### 2.1 数据流

```
采集（DXGI / GDI / 摄像头）
   │
   ▼
统一总线：帧间差分 → 脏区 / 变化率 → 关键帧 / 静默 → 语义 ROI
   │
   ├─ 单帧问答：按档位编码 → 大脑（OpenAI 兼容）
   │
   └─ 双路问答：低清全帧 → 大脑（回答 or zoom）
                        └→ 焦点高清 → 大脑（第二次）
   │
   ▼
对外接口：MCP tools / WebSocket JSON
```

关键约束：`ask` 每次只带当前一帧，历史不累积图片；`ask_fovea` 一次请求最多两张图（低清 + 焦点）。

## 3. 技术方案

### 3.1 采集层

| 源 | 实现 | 状态 |
|---|---|---|
| Windows 桌面 | DXGI Desktop Duplication（ctypes 自研，含 dirty-rects、旋转、区域裁剪） | ✅ 实测 2240×1400，20 帧稳定 |
| Windows 桌面兜底 | GDI BitBlt（含光标） | ✅ DXGI 不可用时自动降级 |
| 摄像头 | OpenCV（DirectShow）；`camera.path` 可指向视频文件做无硬件联调 | ✅ 640×480 视频模拟闭环 |
| macOS / Linux | 接口占位：明确抛 `CaptureUnavailable`，不返回假帧 | 🟡 方案就绪（ScreenCaptureKit / PipeWire + portal） |

采集线程独立，环形缓冲；`get_latest()` 丢弃积压，避免慢消费导致内存增长。

### 3.2 编码层

| 能力 | 机制 | 效果（实测） |
|---|---|---|
| 增量 / 脏区 | `grid_diff` 块级差分，输出 dirty rects 与变化率 | 动态序列图片 token −43.2% |
| 静默 | 无实质变化超过阈值 → `unchanged/silence`，返回缓存图 | 1 h 挂机 30 次问答、内存不涨 |
| 语义安全裁剪 | 检测文字行/连通块，裁剪扩到整行，避免切字 | 修复“21:3 被切成 53” |
| 中央凹 | 围绕焦点裁剪 + 缩放（旧路径） | 单帧图片 token 5.23× |
| 双路喂图 | 低清全帧 + 焦点高清同时给模型 | CAD 命中 4/9 → 7/9 |
| 指令式变焦 | 模型输出 `zoom`，视网膜换算坐标、裁剪、放大 | 8/9 题按需变焦 |
| token 预算 | 按需触发、只裁必要区域、双路总量 ≤ `budget_tokens` | 9/9 单请求 ≤1,800 |
| 场景自适应 | EMA + 滞回三档，控制发送帧率与编码质量 | 低变化 token −32%；动态不降级 |

编码缓存的键是 `(尺寸, 质量, 像素采样签名)`；同一画面重复 `observe` 不会重复编码，`image.cached=true`。

### 3.3 接口层

**大脑（OpenAI 兼容）**

- `POST {base_url}/chat/completions`，图片以 data URI 或裸 base64 放入 `image_url`。
- 配置：`VISION_API_BASE` / `VISION_MODEL` / `VISION_API_KEY`（secrets 文件或环境变量）。
- 健康检查：两张不同纯色图，模型都答对才算视觉可用。

**手（MCP 首选 + WS 兜底）**

- MCP tools：`retina_observe` / `retina_ask` / `retina_ask_fovea` / `retina_set_region` / `retina_list_sources` / `retina_status` / `retina_health`。
- WebSocket `retina.ws/1`：`observe` / `ask` / `ask_fovea` / `ask_actions` / `set_region` / `list_sources` / `status` / `health` / `ping`。
- 产品只返回动作 JSON，**绝不执行**；审批与危险操作由客户选择的手负责。

**隐私与安全**

- 默认不落盘、不上传；`safety.persist_frames=true` 才写文件。
- `safety.region_whitelist` 限定采集区域，越界 `set_region` 抛错。
- 客户模型必须支持视觉输入，健康检查会真实探测并明确报错。

## 4. 能力验证（V1 前后对比）

### 4.1 双路喂图 + 指令变焦 + 预算

素材：两张复绘高清 CAD 图（A1 减速器装配图 3532×2494、A2 教学楼平面图 2970×2100），9 道题（技术特性表 4、标题栏 2、教学楼标题/比例/轴网 3）。

| 指标 | 单帧 baseline | 双路 + 变焦 | 变化 |
|---|---|---|---|
| 命中 | 4/9 | **7/9（78%）** | +75% |
| prompt tokens 合计 | 6,990 | 9,786 | +40.0% |
| 每命中 token | 1,748 | **1,398** | **−20.0%** |
| 单请求超预算 | — | 0/9 | 全部 ≤1,800 |
| 总延迟 | 21.2 s | 34.0 s | +60% |
| 每命中延迟 | 5.30 s | 4.85 s | −8.5% |

- 三条预算全部落地：按需（1 题未变焦，仅 434 token）、裁剪（平均约 5% 画面）、双路受控（最高 1,635 token）。
- 失败样本保留：效率 0.85 被读成 0.97；传动比题模型把变焦框指到“技术要求”区，属于**定位错误**，不是裁剪错误。

### 4.2 场景自适应（暗适应）

| 场景 | 关闭自适应 | 开启自适应 | 变化 |

| 静态（20 s） | 1 帧 / 558 token | 1 帧 / 558 token | 静默先接管 |
| 低变化（20 s） | 40 帧 / 22,320 token | **29 帧 / 15,170 token** | 帧 −27.5%，token **−32.0%** |
| 动态（20 s） | 39 帧 / 21,762 token | 39 帧 / 21,762 token | **不降级** |

### 4.3 动态实时性（修复前后）

| 指标 | full 修复前 → 后 | delta 修复前 → 后 |
|---|---|---|
| 答对 | 8/9 → **9/9** | 7/9 → **9/9** |

修复内容：语义 ROI 安全扩展（不切字）+ 运动/静止强制多帧/差异图；但 120 ms 级闪变仍会漏（见 §6.3）。

### 4.4 单测

`py -3.12 -m unittest discover -s tests`：**27 项全部通过**，覆盖帧/差分、动作解析、编码缓存、区域白名单、静默、双路预算、场景自适应。

## 5. 三阶段对比测试

### 5.1 A：视网膜 vs 专用 OCR

同一批 8 个用例、95 个目标项（CAD 整页 2、真实界面 1、5 个局部裁切）。

| 指标 | 视网膜（采集+识图） | Tesseract 5.4（chi_sim+eng） |
|---|---|---|
| 命中 | **44/95（46.3%）** | 23/95（24.2%） |
| 平均耗时 | 18.5 s | **0.88 s** |
| 成本 | 38,335 token | 0（本地） |
| 界面文字 | **18/20** | 13/20 |
| 减速器整页 | **2/27** | 0/27 |
| 教学楼整页 | **13/27** | 2/27 |
| 标题栏 | **3/3** | 0/3 |
| 技术特性表 / 轴网 | 0/4、0/4 | 0/4、0/4 |

结论：

- 视网膜**懂版面**：标题栏、房间名、图名这类“带位置语义”的文字明显更强；
- 专用 OCR **快且零成本**，但把 CAD 当纯文字流，表格线与文字混排时大量丢失；
- 两者都读不出 3–5 px 的 CAD 小字——这是分辨率上限，不是模型能力；
- 视网膜出现数值幻觉（364→384、20→12），说明“能读”不等于“读对”，必须保留人工复核/二次校验。

报告：`reports/ocr_compare.md`。

### 5.2 B：换大脑

保持采集层与帧完全不变，同一批帧、同一提示词，换两个真实有 Key 的视觉模型。

| 指标 | deepseek-flash | glm-4v-flash |
|---|---|---|
| 命中 | **50/95（52.6%）** | 42/95（44.2%） |
| 平均单张 | 9.5 s | **6.9 s** |
| 中位单张 | 8.8 s | **5.0 s** |
| 总 token | 21,380 | **11,486** |
| 技术特性表 / 轴网 | 0/4、0/4 | 0/4、0/4 |

跳过的模型（不编造结果）：`qwen-vl-max`（无 DashScope Key）、`gpt-4o`（无 OpenAI Key）、`glm-4.5v` / `glm-4v-plus`（HTTP 429）。

结论：

- **接口通用性成立**：换模型只改配置，采集/编码/协议一行没动；
- DeepSeek 图纸略强，但 8 项差距在波动范围内；
- **换更强的模型不能自动解决低分辨率图纸**：两者技术特性表、轴网都是 0/4；
- 幻觉形态不同：DeepSeek 把传动比 20 读成 10；GLM 在技术特性表上整段臆造（“输入电压/高速数据速率/脉冲宽度”）。

报告：`reports/model_compare.md`。

### 5.3 C：vs UI-TARS 等 computer-use 方案

| 维度 | 视网膜 | UI-TARS（native agent） |
|---|---|---|
| 识图方式 | DXGI 脏区 + 语义 ROI；差分/静默/中央凹 | 每步整屏截图 + 历史 |
| token/成本 | 单帧 1,029→184（5.23×）；动态 −43.2% 图片 token | 随步数线性传整屏 |
| 模型/工具绑定 | 模型无关；手走 MCP/WS | 绑定 UI-TARS 模型，感知/推理/动作一体 |
| 跨平台 | Windows 已实现；macOS/Linux 占位 | Web/桌面/Android |
| 隐私 | 本地采集、默认不落盘；接云端仍会离开本机 | 画面必须进入模型 |
| 适用场景 | 给现有大脑/手做低带宽视觉 | 端到端 GUI 自动化 |

结论：**不是“另一个 UI-TARS”，而是低带宽视觉外设**；差异在增量协议、感知解耦、标准接口，不在“谁的 Agent 更强”。

说明：C 是方案级对比，未安装/运行 UI-TARS 本体，不做同机跑分；其“每步整屏”来自论文机制，不是实测 token 数。

报告：`reports/cu_compare.md`。

## 6. 成果与背书

### 6.1 验收总表

| 阶段 | 验收项 | 结果 |
|---|---|---|
| Phase 1 | 客户视觉模型 + 自选手完成 ≥1 个多步闭环 | PASS：4 步 GUI 任务，14.4 s / 5,667 tokens |
| Phase 2 · Token | 单帧 token 降 5 倍 | PASS：962→184（5.23×）；总 prompt 口径 4.1× |
| Phase 2 · 挂机 | 1 h 不溢出 | PASS：3600.4 s，内存增长 −10.9 MB，队列峰值 3 |
| Phase 2 · 双协议 | MCP + WebSocket | PASS：MCP 6 tools（验收时；V1 增至 7）、WS 8 类（V1 增至 9 类） |
| Phase 3 | 桌面/摄像头统一 + 三平台接口 + 现实闭环 | PASS（有缺口）：摄像头 640×480 闭环；macOS/Linux 接口就绪；IDD 方案就绪 |
| 安全 | 白名单 / 健康检查 / 隐私开关 | PASS：越界拒绝、默认不落盘、真实图片探测 |
| V1 双路 | CAD 命中提升且不超预算 | PASS：4/9→7/9；单请求 ≤1,800 |
| V1 自适应 | 静/低变化省 token、动态不降级 | PASS：低变化 −32%；动态帧数不变 |
| 单测 | 核心回归 | PASS：27 项 |

### 6.2 成本控制

- 单帧图片 token **5.23×**；动态序列相对整帧 **−43.2%**；双路按需只多花一次“看清”的钱，每命中 token **−20%**。
- 编码缓存：同画面重复观察不重复编码，`image.cached=true`，`frame_id` 稳定；1 h 挂机 30 次问答仅 27,207 token。
- 联调侧：开发会话的 DSH 统计显示 **prompt 缓存命中约 99%**（会话级数据，仅作成本观察，不是视网膜产品指标）；产品侧对应能力是“编码缓存 + 静默复用”，不是模型厂商的 prompt cache。

### 6.3 诚实边界

1. **不是 Agent**：只输出画面/答案/动作 JSON，不执行、不审批。
2. **Windows only（生产）**：DXGI + GDI 已实测；macOS/Linux 为接口占位。
3. **CAD 识图 78%**：7/9，仍会读错细线数字，也会把变焦框指错区域；A 阶段整页仅 46.3%。
4. **120 ms 级闪变会漏**：端到端约 1.5–2 s，快速红蓝切换可能看到的是“上一帧”。
5. **变焦框依赖模型定位**：模型指错区域时视网膜不纠正（V2 计划加候选区域）。
6. **5.23× 是单帧图片 token 口径**：总 prompt 口径约 4.1×，报告同时披露。
7. **隐私**：本地采集，但接云端模型时画面仍会离开本机；需要完全离线需自托管模型。

## 7. 未来规划

### V2（等摄像头硬件）

- 真实摄像头动态视觉：物体、书本文字、手势、跟随。
- 红外 / 夜视扩展：工业巡检、安防、搜救、无人值守。
- 眼跳多帧采样：缓存最近 N 帧，按问题时刻选帧；对“是否在动”强制多帧/短序列。
- 盲点/区域冗余：白名单之外增加关键区冗余采集，降低遮挡与裁剪误判。

### 开源（占位）

- 代码、协议、单测、报告可公开；`docs/open_source_checklist.md` 已列出红线与白名单。
- 发布前必须：剔除 `artifacts/`、轮换曾落盘的 API Key、替换本机路径/示例名、选定 LICENSE。
- 当前尚未 `git init`，也未确定许可证；开源是计划，不是既成事实。

### 商业化（占位）

- 开放核心（open-core）：核心采集/编码/协议开源，企业版提供多屏/多用户、IDD 虚拟屏、私有化部署与 SLA。
- 不做定价承诺；先验证“客户自选模型 + 自选手”的集成模式能否规模化。

## 8. 结论

1. **V1 目标达成**：仿生双路、指令变焦、token 预算、场景自适应全部落地，27 项单测通过；CAD 命中 4/9→7/9，每命中 token −20%，单请求 ≤1,800。
2. **定位成立**：A/B/C 三阶段分别验证了“懂版面”“换大脑不改采集层”“与 computer-use 方案不同层”；视网膜是低带宽视觉外设，不是 Agent。
3. **省 token 有硬数据**：单帧 5.23×、动态 −43.2%、低变化 −32%，且动态场景不降级。
4. **边界同样硬**：Windows only、CAD 78%、120 ms 闪变会漏、变焦框依赖模型、数值幻觉仍存在；这些已写入能力摘要与验收报告，不藏。
5. **下一步**：等摄像头硬件启动 V2；开源与商业化只做占位，不提前承诺。
