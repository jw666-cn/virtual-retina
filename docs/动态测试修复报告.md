# 动态实时性测试：修复报告（切字 + 静止误判）

- 日期：2026-10-19
- 视觉模型：DeepSeek `deepseek-flash`（推理 + 视觉）
- 测试源：自建 1200×800 动态窗口（时钟 / 运动小球 / 静止 / 红蓝闪变 + 循环视频）
- 题目：同一组 9 题，整帧（full）与增量（delta）各跑一遍
- 范围：仅修复两项缺陷，未改动视网膜对外接口与协议

---

## 1. 修复范围

1. **增量切字**：增量裁剪不得从字符中间截断；裁剪边界按语义 ROI 扩展，文字/符号整行保留。
2. **运动/静止误判**：判断“是否变化 / 运动还是静止”时，强制提供最近 2–3 帧对比，而不是单帧。

---

## 2. 改了什么

### 2.1 新增 `vision_retina/roi.py`（语义安全裁剪）

| 函数 | 作用 |
|---|---|
| `foreground_mask(pixels)` | 灰度 + 中值背景估计（`medianBlur 31`）+ 差分阈值 16 + 3×3 闭运算，得到前景掩码 |
| `_component_boxes(mask)` | 连通域包围盒（过滤 <4 px 噪声） |
| `group_lines(boxes)` | 同一行、水平间距 ≤ `max(10, 0.5×字高)` 的字符合并成一整行文字 |
| `expand_rect_to_content(pixels, rect)` | 迭代扩展裁剪框，直到没有任何文字行“部分相交”；边距只在最后加一次；面积超过全屏 62% 或无法保证安全时返回 `safe=False` |
| `safe_crop_bounds()` | `None` 表示无变化 → 由调用方退回全帧 |

关键修复：旧实现每轮都加 6 px 边距，导致边界不断外扩、最终触发 62% 上限而退回全帧；现在边距只加一次，既保证整行文字完整，又能真正裁小。

回归测试 `tests/test_roi.py`（3 项）：
- 从字符中间切 → 扩展后包含整行；
- 面积上限 → 安全失败并退回全帧；
- 同一行字符分组为一行。

### 2.2 测试层 `tools/dynamic_test.py`

- 语义 ROI 表 `ROI_BY_KIND`：
  - `clock`：顶部 0–18%；
  - `ball` / `direction` / `static`：中部 28–60%（避开左下角循环视频）；
  - `color` / `bgchange`：全屏（背景色判断必须看全屏）。
- `build_delta()`：先筛与语义 ROI 相交的脏区，取并集并与 ROI 合并，再调用语义安全扩展；不安全则整帧。
- 多帧判断：
  - `static3`：3 帧 + 第 4 张“首末帧差异放大图（越黑越静止）”；
  - 颜色/背景：2 帧，间隔 2 s，闪变周期 2 s，红/蓝确定；
  - 静止三帧间隔 1 s，限制在 STATIC 窗口内（10.5–12.5 s），避免第三帧落入闪变阶段。
- 每次采集前 `capture.drain()`，避免拿到窗口切换前的旧帧。
- `temperature=0.0`、`max_tokens=2048`、单题 100 s 超时、逐题增量落盘、`--save-crops` 保留每题实际输入图。

### 2.3 测试床 `tools/dynamic_window.py`（仅测试用）

- FLASH 背景 2 s 周期确定切换（红 16–18 s、蓝 18–20 s），不再依赖毫秒随机相位；
- 时钟/小球/静止/闪变与题目的时间窗对齐；
- 窗口置顶并输出客户区几何 `artifacts/dynamic/window_geom.json`。

## 4. 是否仍有切字 / 静止误判

### 切字：已消除（本题组）

- 修复前 q5：裁剪把 “22:2x” 切成 “53”，309 tokens、19.5 s、答错。
- 修复后 q5：裁剪图 900×116 完整包含 `22:23:33.496`（含毫秒与副标题），310 tokens、1.37 s、答对。
- q1/q5 两次时钟题全部答对；保存的裁剪图逐张检查无半字、无截断。
- 语义扩展在无法保证安全时直接退回整帧，因此“宁可多给、不会切字”。

### 静止误判：已修复（本题组）

- 修复前 q4：单帧 → 模型答“运动”。
- 修复后 q4：3 帧并排 + 差异图（全黑）→ 答“静止”；最终 full 与 delta 各跑一遍均通过。
- 闪变题改为 2 s 确定周期后，q7 由“两帧同红”变为稳定的“红→蓝”。

## 5. 剩余问题

1. **颜色/背景题仍用全帧**（q6/q7），因为背景色判断需要看全屏；这两题占了增量 token 的主要部分。
2. **组合题 q8 仍为全帧**（579 tokens）：两帧方向需要较大视野，当前共用裁剪框退化为整帧。
3. **延迟长尾**：修复后最大 1.77 s，但模型 reasoning 长度波动时仍可能到 5–13 s；测试用 `temperature=0`、`max_tokens=2048` 压低了长尾，产品侧需保留超时重试。
4. **测试床依赖前台窗口**：窗口被其他窗口遮挡时，采集区域会拍到遮挡内容；正式产品应使用独立虚拟屏/IDD 或区域白名单。
5. **模型对“变化”语义仍有波动**：差异图+温度 0 后本题组稳定，但不能保证所有画面都一次答对；安全关键场景应由总线先做像素级变化判定，再让模型解释变化内容。

---

## 6. 建议

- 颜色/背景类问题改为“多区域拼图”（顶部/中部/底部各一块）而不是整帧，可继续压 token。
- 把差异图生成下沉到产品总线，对外暴露“是否变化 / 变化区域”的结构化结果，模型只负责语义解释。
- 对时钟等文本区域使用固定 ROI + 语义安全裁剪双层策略，兼顾 token 与完整性。
- 增量模式保留“安全失败即整帧”的兜底，并在返回元数据中标记 `crop_safe`，便于上层判断。
