## 4. Phase 2：Token 与增量

| 模式 | 尺寸 | prompt tokens | JPEG bytes | 延迟 ms | 复用上帧 |
|---|---|---|---|---|---|
| full-native | 2240×1400 | 1029 | 256904 | 1829 |  |
| fovea-240-0.66 | 317×317 | 251 | 3673 | 1442 |  |
| fovea-240-0.5 | 240×240 | 251 | 2573 | 1430 | 是 |
| fovea-200-0.5 | 200×200 | 251 | 1929 | 1072 | 是 |
| fovea-180-0.5 | 180×180 | 251 | 1442 | 1386 | 是 |
| region | 800×600 | 384 | 37661 | 2273 |  |
| cached | - | 1029 | — | 2141 | 是 |

- 文本-only prompt=67；单帧图片 token：全帧 962 vs 中央凹 184，**5.23x**（verdict=PASS）。
- 口径：同一 system+prompt，仅图片不同；差值即图片 token。全帧/中央凹的总 prompt 比是 4.1x（差值被固定文本摊薄）。
- 中央凹 180–317 px 都落在模型“单图块”下限，token 相同，因此默认取 240/0.66 保留更多细节。
- 静默/未变化时不再重新采集与编码，`retina_observe` 返回最近一帧并标记 `image.cached=true`；`ask` 仍会把这一帧交给模型（视觉问答必须有图），但帧 ID 保持稳定、历史不累积图片。
- 默认 `bus.mode=delta`：无变化时立即返回 unchanged（不等新帧）；静止超过 `silence_timeout_s` 记为 silence。
- 消费端始终取最新帧（`get_latest` 丢弃积压），高帧率/慢网络下不会看到过期画面，队列长期保持 0–3 帧。- 上下文替换：每次 `ask` 只带当前一帧，历史不累积图片；`ask_actions` 的历史只有文本动作。

## 9. 缺口与风险

1. **macOS / Linux 实现未完成**：仅接口与方案；需要真机 + 权限（Screen Recording / portal）验证。
2. **IDD 虚拟屏未构建**：内核驱动需 WDK、测试签名、管理员与重启；当前机器有真实显示器，不影响 Phase 1–3。
3. **实体摄像头未接入**：按 §10 占位；视频文件模拟已验证同一管线。
4. **手未锁定**：按 §10 由客户选择；本报告用本地测试手 + 通用 MCP 客户端验证，产品不绑定任何手。
5. **Token 口径**：5 倍是“单帧图片 token”口径（962→184，5.23x）；若按总 prompt（含固定指令文本）为 4.1x，因为固定文本不随图像缩小。建议产品文档明确口径。
6. **MCP stdio 未在 DSH 沙箱内验证**：沙箱禁止命名管道；已用 Streamable HTTP 验证同一套工具。
7. **模型推理 token**：deepseek-flash 会先推理再回答，`max_tokens` 过小会出现空 content（finish_reason=length）；默认 1024 已规避，健康检查用 512。
