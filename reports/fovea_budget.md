# 仿生双路喂图 + 指令式变焦 + token 预算联动：验证报告

> 对应 V1.2 / V1.3 / V1.4。实现：`vision_retina/bionic.py`；预算与 ROI 复用 `vision_retina/roi.py`。
> 验证脚本：`tools/fovea_budget_eval.py`；原始数据：`artifacts/fovea_budget/results.json`。
> 日期：2026-10-20；模型：`deepseek-flash`（temperature=0）。

## 1. 目标与口径

仿生依据：视杆看全局（低清全帧）、视锥看细节（焦点高清）、中央凹可编程（模型指定放大区域）。

三条预算原则：

1. **按需触发**：模型先看低清全帧；只有它输出 `zoom` 指令才发第二次请求，不盲目放大。
2. **裁剪到位**：只裁模型指定的矩形（坐标按低清图→原图等比换算），再做语义安全扩展，避免切断文字。
3. **双路受控**：低清全帧 + 焦点高清的**图片 token 估计值**必须在 `budget_tokens` 内；超预算则缩小焦点，仍超则拒绝变焦、直接返回第一次回答。

token 估计式（与实测校准）：`tokens ≈ 570 × sqrt(width×height/1e6)`；低清图 640 宽约 434 token，1024×1024 约 584 token。

## 2. 请求协议

第一次请求附系统指令，要求模型二选一：

```json
{"action":"answer"}
```

或

```json
{"action":"zoom","region":{"x":120,"y":80,"w":300,"h":140},"reason":"表格数字太小"}
```

`region` 使用**低清图坐标**；视网膜按 `原图宽/低清宽` 换算，再裁剪、语义扩展、必要时上采样到 `focus_max_width`。第二次请求同时带低清全帧与焦点图，并告知"这是同一画面的放大图"。

## 3. 验证设置

- 素材：`artifacts/cad_redraw/减速器装配图_复绘.png`（3532×2494，A1）、`artifacts/cad_redraw/教学楼一层平面图_复绘.png`（2970×2100，A2）。
  > 原扫描图（1280×905 / 1440×1020）字高只有 3–5 px，放大也无信息，故改用同项目复绘的高清矢量图作为"可读性上限"样本。
- 9 道题：技术特性表 4 项（输入功率、高速轴转速、效率、传动比）、标题栏 2 项（名称、比例）、教学楼标题/比例/轴网尺寸 3 项。
- 对照：
  - **baseline**：单张全帧，`max_width=1200`，同一提示词、同一模型。
  - **bionic**：低清 `max_width=640` + 按需焦点，`budget_tokens=1800`。
- 判分：数值/文本归一化后包含匹配；空回答判错。

## 4. 结果

| # | 题目 | 期望 | baseline | bionic | 变焦框（原图像素） |
|---|---|---|---|---|---|
| 1 | 输入功率 | 3.5 | ✗ "3" / 778 tok | ✓ "3.5" / 1,145 tok | 603×355 |
| 2 | 高速轴转速 | 364 | ✗ 空 / 780 | ✓ "364" / 1,201 | 840×576 |
| 3 | 效率 | 0.85 | ✗ "0.97" / 776 | ✗ "0.97" / 1,635 | 659×907 |
| 4 | 传动比 | 20 | ✗ "3.1" / 777 | ✗ "无法辨认" / 1,326 | 1017×907（框错，落到技术要求区） |
| 5 | 图纸名称 | 两级圆柱齿轮减速器 | ✓ / 776 | ✓ / 1,033 | 1116×382 |
| 6 | 比例 | 1:2 | ✓ / 775 | ✓ / 985 | 1017×355 |
| 7 | 教学楼标题 | 教学楼一层平面图 | ✓ / 774 | ✓ / **434（未变焦）** | — |
| 8 | 教学楼比例 | 1:200 | ✓ / 773 | ✓ / 1,006 | 940×349 |
| 9 | 轴线 9–10 | 1800 | ✗ 空 / 781 | ✓ "1800" / 1,021 | 581×233 |

汇总：

| 指标 | baseline | bionic | 变化 |
|---|---|---|---|
| 命中 | 4/9 | **7/9** | +3（+75%） |
| prompt tokens 合计 | 6,990 | 9,786 | +40.0% |
| 每命中 token | 1,748 | **1,398** | **−20.0%** |
| 总延迟 | 21.2 s | 34.0 s | +60% |
| 每命中延迟 | 5.30 s | 4.85 s | −8.5% |
| 单请求超预算 | — | 0/9 | 全部 ≤1,800 |
| 变焦请求 | — | 8/9 | 1 题按需跳过 |

单请求最高 prompt 1,635 token（第 3 题），仍在 1,800 预算内；`bionic_estimated`（低清+焦点估算）合计 7,540，与实际 9,786 的差额来自 system/提示词与模型侧模板 token。

## 5. 结论

1. **命中提升明确**：4/9 → 7/9。原来看不清的表格小字（功率、转速）与轴网尺寸，在"模型点名放大"后读对。
2. **预算三条全部落地**：按需（第 7 题未变焦，仅 434 token，比 baseline 省 44%）、裁剪（8 次变焦平均只覆盖约 5% 画面）、双路受控（9/9 在 1,800 内）。
3. **总 token 上升但单命中成本下降**：多出的 token 花在"多看一次细节"，每命中 token 反而降 20%。
4. **仍有两类失败**：
   - 第 3 题效率 0.85 被读成 0.97——放大后仍受 CAD 细线字体与 JPEG 影响，属于模型读数误差；
   - 第 4 题模型把变焦框指到"技术要求/明细表"区域而不是技术特性表，属于**目标定位错误**，不是裁剪错误；报告保留原始失败样本，不做事后挑选。

## 6. 复现

```powershell
py -3.12 -u tools/fovea_budget_eval.py --budget 1800 --low-width 640
```

输出：`artifacts/fovea_budget/results.json`；单测：`py -3.12 -m unittest discover -s tests`（27 项）。

## 7. 限制

- 变焦框由模型给出，模型指错区域时视网膜无法纠正（可加"候选区域列表"作为 V2）。
- 焦点图清晰度受原图分辨率上限约束；扫描件 3–5 px 字高无法靠放大补救。
- token 估计是近似式；不同厂商的图像计费不同，预算应按客户模型校准。
- 每题两次串行请求，延迟高于单帧；适合"看不清才看"，不适合每帧都变焦。
